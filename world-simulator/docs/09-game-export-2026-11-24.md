# 09 — Game export: the simulator's people in the game

PR9 covers the first slice of the master plan's phase "PR11 — Game export and runtime
integration". The residents who walk a town's streets in the Drusniel game are now the
simulator's named people, where an export covers the town. The game side is described in
[world-sim residents](../../docs/world-sim-residents-2026-11-24.md).

## The export

`POST /api/scenarios/{id}/export/game` writes the export into the game's `public/world-sim/`
(`gameExport.directory` in `config/simulator.yaml`, or `WS_GAME_EXPORT_DIR`). No request names
a path. `GET` on the same address returns the same documents without writing them.

| File | Contents |
|---|---|
| `index.json` | Schema `drusniel-world-sim-game-export` version 1, map and source fingerprint, scenario, date, state checksum, and one row per settlement with its file |
| `settlements/<sourceId>.json` | The same header, the settlement, and its residents |

**Who is exported.** Every living named person in the settlement, except outlaws (out on the
road) and prisoners. Each resident has:
- **Identity:** id, name, family, sex, age, role, profession, tier, household, home.
- **Work:** their workplace (name, kind, sector).
- **State of mind:** mood, up to three hooks.
- **Words:** an introduction, and a short biography when one is written.

Residents are ordered by prominence (major, standard, basic tier), then by role.

**Identity.** People keep their `npc:<sourceId>:<n>` id across exports, saves and the game.
Settlements join on the Azgaar burg number: the game's `settlement.id` is the simulator's
`sourceId`.

**Introductions.** These are the stored model prose ("In their own words") when it is
current. Otherwise the draft writer's sentences, which come only from the record. An
export is deterministic for a given state and stored prose. A settlement file no longer
listed is removed on the next write.

**The committed export.** `public/world-sim/` holds the pilot baseline (1212-01-01; 27, 18
and 41 residents in Sshanderi, Falanenerwin and Vhaltha) with draft-writer introductions,
so the game shows named people without the simulator running. Re-export to show a scenario
further on, or with model prose.

## Not in this PR

- **Meetings back to the simulator:** the game remembers who the player has met, in the
  browser. Those meetings are not yet imported into the scenario as `met-player` events.
  The simulator's API refuses cross-site writes by design, so this needs an import step.
- **Dialogue in the game:** the nameplate shows an introduction or a concern, but there is
  no conversation in the game yet.
- **Homes and schedules:** the simulator's dwellings are not matched to the game's houses,
  and residents do not follow a time of day.
- **Children** are exported but not shown, because there is no child model.
